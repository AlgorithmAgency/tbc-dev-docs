Before You Begin

Prerequisites — Confirm All Before Starting

  • WordPress site with admin access
  • Gravity Forms Elite licence installed & activated
  • Gravity Forms Zoho CRM Add-On installed (Elite includes this)
  • Access to The Building Company Zoho CRM — correct org
  • Zoho CRM paid plan active (required for API access)
  • Buco SA branch list confirmed — all branch names and manager emails
  • Buco SA privacy policy URL confirmed
  • Lead Source picklist values added to Zoho CRM (see Section 05)
!
Branch List & Email Addresses — Collect Before Building
This is the most common setup blocker — sort it first

Before building any forms, collect the following from your Buco SA contact:

  • Complete list of all Buco SA branch names — exactly as they should appear in the dropdown
  • Branch manager email address for every branch
  • A head office or customer care email to use as a catchall for any branches missing a manager email
⚠️
Branch names in the GF dropdown must match the conditional logic values in notifications exactly — spacing and capitalisation included. Finalise the branch list before building the form so you don't have to update both the dropdown and 30+ notifications later.
💡
For branches where no manager email is available yet, use a catchall like customercare@buco.co.za as a temporary placeholder. Update to the correct email once received from the client.

Connect Zoho CRM

One-time OAuth connection per WordPress site

01
Navigate to the Zoho CRM plugin settings
Plugin-level settings — not an individual form
WordPress Admin → Forms → Settings → Zoho CRM

You should see a button: "Click here to connect to Zoho CRM". If it already says "Connected to Zoho CRM", skip to step 3.

02
Complete the OAuth authorisation
Log in with The Building Company's Zoho account — not a personal account

Click the connect button. You will be redirected to Zoho's login page.

⚠️
You must log in to the correct Zoho organisation (The Building Company). Logging in with a personal or test account will send leads to the wrong CRM.

Select region: zoho.com. Authorise all requested permissions. You will be redirected back to GF showing "Connected to Zoho CRM."

03
Clear the Custom Fields Cache
Makes custom fields visible in GF feed mapping

On the same Settings → Zoho CRM page, click "Clear Custom Fields Cache".

💡
GF caches Zoho field data for 12 hours. Clearing manually ensures your custom fields (Branch, Brand, Topic) are available immediately. If they don't appear in feeds later, come back here and clear again.

Configure Branch Notifications

One email notification per branch — conditional logic routes each submission to the correct manager

01
Navigate to Notifications for your form
Forms → [Your Form] → Settings → Notifications → Add New
02
Fill in the notification fields
Set this up for your first branch — you'll duplicate it for all others
FieldValue
NameBranch — [Branch Name]
Send ToEnter Email (select this radio button)
Send To EmailBranch manager's email address
From NameBuco SA
From Email{admin_email} (leave as default)
Reply ToClick {...} and select the Email field
SubjectNew Enquiry — Buco SA [Branch Name]
💡
Setting Reply To to the customer's email means when the branch manager hits Reply, it goes directly to the customer — not to the WordPress admin email.
03
Write the message body
Use GF merge tags — click {…} to browse or type field IDs directly

Check your field IDs by clicking each field in the Form Editor — the ID shows in the top-right of the Field Settings panel.

The Name field uses sub-IDs: FIELD_ID.3 = First Name, FIELD_ID.6 = Last Name.

Message Template — replace X with your actual field IDs
You have received a new enquiry via the Buco SA website. Name: {Name (First):X.3} {Name (Last):X.6} Email: {Email:X} Phone: {Mobile Phone:X} Branch: {Branch:X} Message: {Message:X}
04
Enable Conditional Logic
Without this, every branch receives every submission

Scroll to the bottom of the notification. Tick "Enable conditional logic".

Send this notification if ALL of the following match: Branch | is | [Branch Name]

Save. The notification should appear in the list with an Active badge.

05
Duplicate for all remaining branches
Hover over the notification in the list → Duplicate option appears

For each duplicate, only change these 3 things:

  • Notification Name — update to the new branch name
  • Send To Email — update to that branch manager's email
  • Conditional Logic value — update the branch dropdown value to match

Message body, From Name, Reply To, and Subject format all carry over from the duplicate.

CRM Feed Mapping

Maps GF form fields to Zoho CRM lead fields — done once per form

01
Add Lead Source value to Zoho CRM picklist first
Must exist in Zoho before the feed will map it correctly

Before creating the feed, go to Zoho CRM and add your Lead Source values to the picklist:

Zoho CRM → Setup → Leads → Fields → Lead Source → Edit

Add the following values if they don't already exist:

Buco SA Website - Contact Us Buco SA Website - Request a Quote
⚠️
If the Lead Source value doesn't exist as a picklist option in Zoho, it will not map correctly through the GF feed. Add it here first, then proceed to create the feed.
02
Create a new Zoho CRM feed
Form → Settings → Zoho CRM → Add New
SettingValue
Feed NameBuco SA — Contact Us
ActionCreate a New Lead

Click Save Settings → to reveal the full field mapping section.

03
Map the standard fields
Company→Brand (hidden field — shows "Buco SA")
Email→Email
First Name→Name (First)
Last Name→Name (Last)
04
Map custom fields using Key / Value rows
Click + to add each row — use Custom Key if fields don't appear in the dropdown
⚠️
Custom fields like Branch and Brand may not appear in the Key dropdown. If they don't, select Custom Key and type the field name manually. Spelling is case-sensitive — copy exactly as shown below.
Phone→Mobile Phone (GF field)
Branch→Branch (GF dropdown field)
Brand→Brand (hidden field)
Lead_Source→Lead Source (hidden field)
05
Map Lead Description and set Options

Scroll to Lead Description. Click {...} and select the Message field.

Under Options:

  • Tick "Allow duplicate leads"
  • Leave everything else unticked

Leave Lead Owner, Lead Rating, Lead Source dropdown, Lead Status all as -None-. Click Save Settings →

POPIA Consent Field

Required for South African compliance — must be on every form before go-live

01
Add a Consent field to the form
Use the GF Consent field type — not a standard checkbox

In the Form Editor, under Advanced Fields, add a Consent field. Place it directly above the Submit button.

SettingValue
Field LabelConsent
Checkbox LabelI agree to the privacy policy.
Required✅ Yes
02
Add the consent description with a linked Privacy Policy
The Description field supports HTML — use it to add the live link

In the Description field of the Consent field settings, paste the following HTML — replacing the privacy policy URL with Buco SA's actual URL:

Consent Description HTML
I consent to Buco SA collecting and processing my personal information submitted in this form for the purpose of responding to my enquiry. My information may be shared with the relevant branch and sales team. It will be handled in accordance with the Protection of Personal Information Act (POPIA) and <a href="https://buco.co.za/privacy-policy/" target="_blank"> Buco SA's Privacy Policy</a>. I understand I may request access to or deletion of my personal information at any time.
💡
Replace https://buco.co.za/privacy-policy/ with the actual Buco SA privacy policy URL. Confirm this URL exists and is accessible before go-live.

Test & Verify

Always test before going live — check both GF entry notes and Zoho CRM

01
Submit a test entry on the live form

Navigate to the live form on the front-end. Fill in all fields. Select a specific branch. Include a message. Tick the consent checkbox. Use a real email address.

02
Check GF entry notes for errors
Fastest way to catch CRM mapping errors
Forms → [Your Form] → Entries → [Test Entry] → scroll to Notes
✅
Lead created. ID: [number] — CRM feed worked correctly.
✅
WordPress successfully passed the notification email to the sending server — branch notification sent.
✗
The field [X] cannot be found at Zoho CRM — custom key spelling mismatch. See Section 10 Troubleshooting.
03
Verify the lead in Zoho CRM

Go to Zoho CRM → Leads and find your test lead. Confirm:

  • Name, Email, Phone
  • Company = Buco SA
  • Lead Source = Buco SA Website - Contact Us
  • Branch = the branch selected in the form
  • Brand = Buco SA
  • Description = the message typed
  • Layout = Website Lead Layout
04
Verify the branch notification email
  • Email arrived in the correct branch manager's inbox
  • All form data visible in the email body
  • Reply-To is the customer's email address
  • No other branch managers received it

03
Disable the default Admin Notification
Branch notifications handle all routing — the Admin Notification is redundant

When GF creates a new form it automatically adds an Admin Notification that fires on every submission and sends to the WordPress admin email. Since each branch manager has their own conditional notification, this is unnecessary and creates noise.

Form → Settings → Notifications → hover Admin Notification → Disable
💡
Disabling does not delete it — you can re-enable at any time. If you want a head office catchall instead of disabling, update the Send To Email on the Admin Notification to a Buco SA head office address.

Troubleshooting

Common errors and how to resolve them

⚠️
The field [Branch / Brand] cannot be found at Zoho CRM

Cause: The Custom Key in the GF feed doesn't match the field's API name in Zoho CRM. Case-sensitive.

Fix: Check the key spelling exactly. Use Branch not branch, Lead_Source not Lead Source. Go to Zoho CRM → Setup → Leads → Fields to verify exact field names.

⚠️
Branch / Brand not appearing in the Key dropdown

Cause: GF has cached an older field list that doesn't include custom fields.

Fix 1: Go to Forms → Settings → Zoho CRM → Clear Custom Fields Cache, then return to the feed.

Fix 2: Select Custom Key from the dropdown and type the field name manually. Works identically to selecting from the dropdown.

⚠️
Branch and Brand not visible on the lead record in Zoho CRM

Cause: Lead is using Standard layout, which doesn't include custom fields. Data is present but not displayed.

Fix (individual lead): Open the lead → Edit → Change Layout → Website Lead Layout.

Fix (all future leads): Setup → Leads → Layouts → Layout Assignment → set Website Lead Layout as default for Administrator.

⚠️
Lead already exists — second test submission blocked

Cause: Same email used twice. Zoho blocks duplicates unless "Allow duplicate leads" is ticked.

Fix: CRM feed → Options → tick "Allow duplicate leads". Or use a different email for subsequent tests.

⚠️
Wrong branch manager received the notification

Cause: Conditional logic value doesn't exactly match the branch dropdown option.

Fix: Open the notification → Conditional Logic → check the branch value matches exactly, including spacing and capitalisation (e.g. East London (Beacon Bay) not East London).

⚠️
Lead Description / Message not appearing in CRM

Cause: Message mapped as a Custom Key row instead of the dedicated Lead Description field.

Fix: Remove the Description custom key row. Scroll to Lead Description text area → click {...} → select the Message field.

⚠️
Lead Source not mapping — value not found in Zoho

Cause: The Lead Source value (e.g. Buco SA Website - Contact Us) doesn't exist as a picklist option in Zoho CRM's Lead Source field.

Fix: Go to Zoho CRM → Setup → Leads → Fields → Lead Source → Edit picklist and add the missing value. Then retest the form submission.
